# SNES OSD2のFPGA側USB P1・P2入力

2026年11月16日（日本時間）。Console138Kでスーパーマリオカートの2人用バトルモードを1回起動した。P1がOSD2を操作できることと、P2の入力がゲームに漏れず、両方のボタンを離した後に通常操作へ戻ることを実機で確認した。

- firmware `95871ef8e9ef547767b145cee4e85577e8bb4972`
- SNESTang `9a1360fd764b7ca85e3b0013ac684a36ec3a04a9`
- ROM ID `c8002453`（ROMのCRC32）

## 実機手順と結果

| 確認 | 操作 | 観測結果 |
| --- | --- | --- |
| 通常操作 | FPGA側USB P1とP2でそれぞれのカートを操作する | 両方とも自分のカートを操作できた |
| OSD2の呼出し | P2単独でSELECT＋左。全解放後にP1のSELECTとP2の左を同時に押す | どちらの操作でもOSD2は開かなかった |
| OSD2の操作 | P1のSELECT＋左で開き、P2の下とSTARTを個別に押す。その後P1のSTARTを押す | P2では選択位置や表示が変わらず、P1では補助表示が開き `APPLY: FRAME ACK` が出た |
| ゲーム入力の遮断 | OSD2表示中にP2の加速ボタンを保持し、P1のXかYで閉じる | 表示中も、閉じてからP2がボタンを保持している間も、P2は加速しなかった |
| 全解放後の復帰 | 両方の全ボタンを離してから押し直す | P1・P2とも通常操作に戻った |

実機での観測結果はユーザー報告に基づく。SAVE・RESETは各0回。microSDは本体に装着した状態で試験を終えた。今回の試験後のmicroSDの内容比較は未実施。DS2とBL616側USBの経路は別の試験範囲となる。

## PCでの再現

親repositoryが参照するfirmwareで、既存の `crt_test.cpp` と今回の `osd2_usb_p1_p2_test.cpp` を実行する。今回の試験は製品のOSD2入力処理へP1・P2の値を与え、P2の方向・START・戻る操作で画面が変わらないこと、P1のSTARTで補助表示へ切り替わること、全解放待ち中は次の操作を受け付けないこと、P2がボタンを保持している間もP1がOSD2を閉じられることを確認する。ゲーム入力の遮断と復帰は、上表の実機結果で確認した。

```powershell
python tools/test_osd2_usb_p1_p2.py --firmware firmware-bl616 --output ../osd2-usb-p1-p2-pc
```

WindowsのMSYS2 UCRT64を使う場合は、必要に応じて `--cxx C:/msys64/ucrt64/bin/g++.exe --cxxflag=-BC:/msys64/ucrt64/bin/` を指定する。

実機とPCの結果は `verification/osd2-input-usb-p1-p2-20261116/` に記録した。
