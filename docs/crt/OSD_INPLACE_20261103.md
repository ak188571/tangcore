# OSDの項目切替時に表示を維持する修正

2026年11月3日、第1段階の実機試験で、NESの映像・音声・操作、OSD2の独立起動、設定変更後のFRAME ACKが正常との報告を受けた。同時に、項目を切り替えるたびにOSDが一瞬消えることが指摘された。

## 原因と変更

既存の描き直しは、OSD領域の幅・高さを0へ変更し、文字領域全体を消去してから、全項目と表示領域を送信していた。選択位置だけの変更でもこの処理を実行するため、OSDが一時的に非表示になっていた。

修正版は現在のOSDを表示したまま、前回と異なる文字の連続部分だけを上書きする。通常の選択変更では、前の選択印と新しい選択印の2文字が対象になる。設定値やFRAME ACKの表示も同じ方法で更新し、短くなった文字列の末尾は空白で上書きする。

表示位置や大きさが変わる場合は、新しい領域の文字を書き終えてから領域情報を送る。別画面が文字領域を書き換えた可能性がある場合は、保存していた前回表示を無効にし、必要な領域を再送する。これらの更新でも、描き直しのために幅・高さを0へ変更する処理は使わない。

変更はBL616 firmware側だけであり、NES coreの再生成は不要。前回表示の保存領域は静的に確保し、UI taskのstackへ追加しない。

## 検証

- 実際のOSD操作loopへ擬似的な文字RAMを接続し、送信された文字を再現して表示内容を照合した。
- 選択変更、設定値変更、文字列が短くなる場合、別画面から戻る場合を確認した。
- 通常の選択・値変更で、領域非表示と画面全消去が発生しないことを確認した。
- 中央と四隅への配置、スクロール、既存OSD操作、CRT設定、起動処理の試験が成功した。
- Console138K向けfirmwareのbuildが成功し、custom領域に収まることを確認した。
