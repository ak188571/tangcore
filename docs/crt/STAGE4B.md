# 4b 走査線と設定反映の修正

Console138K／NESの実機確認済みtag `crt-stage4a-hw-20261103` を基準にする。4b初版は導入済みだが、実機試験で設定の取りこぼしと走査線間隔の問題が見つかった。4bは未完了とし、修正版の実機確認後に段階5へ進む。GitHubへのpushは行わない。

## 初版の実機結果と修正方針

2026年11月3日の初版試験で、通常の映像・音声・操作、ぼかしと走査線の併用、表示位置の維持、OSD文字への効果の非適用は正常との報告を受けた。一方、OFFに対して映像がWEAK相当になるなど、ぼかし・走査線の要求値と映像が一致しない場合があった。この状態のAPPLYはFRAME ACKではなくWAITINGであり、追加操作までWAITINGが続く場合もあった。表示文字だけの問題として扱わない。

初版は各元走査線に対応する3〜4表示行の最後の1行を暗くしたため、暗い帯の間隔が不均等に見えるとの報告もあった。利用者は、元224走査線との対応を保ち、隣接する表示行へ明暗を配分して段差を和らげる方式を選択した。固定3表示行周期の240本へは変更しない。

## 設定転送とAPPLY

実UART試験で、FPGAの受信状態が返信完了待ちに入り、その間の設定packetの先頭を失うことを再現した。状態問い合わせ直後に設定を送る試験は、導入済みNES commit `08766efb13ed06cc14134d644067b34fe03d9b70` の受信処理では失敗し、修正版では成功する。これはWAITINGが操作なしでは収束しない原因になり得る。実機症状の全要因をこの試験だけで断定はしない。

修正版では返信中も受信を停止させない。送信中の返信typeは維持し、次の問い合わせを別の1件のpending slotへ保持する。slot使用中の追加問い合わせは最新typeへまとめる。設定・OSD・ROM packetは継続して受信する。起動時のcore ID／能力問い合わせは既存の順次送信を維持する。

BL616はOSD2表示中に約100 msごとに適用済み設定を問い合わせ、要求したCRT領域と返信値が一致した場合だけFRAME ACKにする。WAITINGが250 ms続けば最後の要求値を再送する。同じ値の上書きであり、別の強度へ進めない。古い設定への返信を新しい要求のACKにしない。経過時間だけではFRAME ACKにせず、返信がなければWAITINGを維持する。

A/Bによる設定変更ではbutton解放までOSDの処理を停止させない。押したままでも値・APPLYの描画、問い合わせ、再送を続ける。押下edgeで1回だけ変更する。通常のdialog後の解放待ちは維持する。

`core_config` bit 16は共通の有効flag、18:17はぼかし、20:19は走査線の強度0〜3である。clock domain間転送とframe境界での一括反映は既存方式を継続する。FRAME ACKはframe境界で適用した設定の返信であり、画質評価の代わりにはならない。

## 元走査線に対応する明暗配分

既存scalerの `ycnt` は表示行ごとに224を加算し、720で折り返す。frame開始時の初期化をそのまま使い、別の行counterは追加しない。pをその位相とすると、表示1行が覆う元位相の幅は224、暗い帯は各元走査線の末尾496〜720である。表示行の範囲p〜p+224と帯の重なりoを求める。720を越えた部分の次の元走査線先頭は明るい。

```text
o = max(0, min(p + 224, 720) - max(p, 496))
d = floor((o × D + 112) / 224)
RGB出力 = floor((C × (16 - d) + 8) / 16)
```

Cは各8 bit RGB入力、Dは選択強度の最大減光量、dは当該表示行の減光量。最近整数へ丸め、ちょうど半分は切り上げる。

| SCANLINE | D | 最も暗い行のRGB係数 | 白255の最小出力 |
| --- | --- | --- | --- |
| OFF | 0 | 1 | 255 |
| WEAK | 2 | 14/16 = 7/8 | 223 |
| STANDARD | 4 | 12/16 = 3/4 | 191 |
| STRONG | 8 | 8/16 = 1/2 | 128 |

明暗は1/16刻みで隣接行へ配分する。位相は16の倍数だけを通るため、回路は除算せず45位相に対する場合分けで計算する。1 frameのdの総和はWEAKで448、STANDARDで896、STRONGで1,792となり、係数の積分値は初版の224本分の暗さと一致する。RGBの整数丸め後の総和まで必ず一致するという意味ではない。

元224行を保つため、帯の中心が常に整数の表示行に重なるわけではない。幾何学的な3〜4行周期を消す仕様ではなく、濃さの分配で段差を和らげる。frame間で模様を動かさない。改善と強度の好みは再度実機で確認する。この位相生成は今回のNES用であり、他coreには別途対応する。

## 映像経路と位置の維持

順序は「色変換・拡大→水平ぼかし→走査線→OSD合成→HDMI」。OSD文字・panel領域へ効果を掛けない。gamma変換は追加せず、RGB値への係数として扱う。黒は0を維持する。

| 有効な効果 | memory先読み | 処理内部のRGB保持 |
| --- | --- | --- |
| なし | なし | なし |
| ぼかしのみ | 3 pixel clock | 色変換RGB＋中央画素保持＋ぼかし結果 |
| 走査線のみ | 1 pixel clock | 色変換RGB |
| ぼかしと走査線 | 3 pixel clock | 色変換RGB＋中央画素保持＋ぼかし結果 |

減光にはregisterで保持したRGBだけを入力し、長い色変換・ぼかし・減光の組合せ経路を避ける。位相から計算したdもregisterに保持し、表示開始前の余白で当該行の値にそろえる。明暗でRGB保持段数を変えない。frame buffer・行bufferは追加しない。

本修正の合成reportでは全体のBSRAMが31から32、MULT12X12が1から4へ増加している。生成されたnetlistでは既存の色paletteとRGB保持を1個のpROMへ対応付け、減光の3色の乗算に3個のMULT12X12を使用している。映像を保存するframe bufferや行bufferの追加ではない。物理的な資源数はRTLのregister表記だけから推測せず、対象buildのreportで確認する。

先読みと保持を相殺し、RGB、OSD、HDMIの位置を維持する。CRT ENABLEがOFF、または両効果OFFの場合は従来RGBとmemory読出し時刻を維持する。走査線だけがONなら初版より1 pixel clock早い読出しとなる。ぼかし有効時は4aより2 pixel clock早い。従って、動いている映像memoryの同じ場所の書換えと読出しが重なる場合まで旧版とのbit一致を保証するものではない。動く場面も実機確認対象とする。

## 能力通知とOSD2

能力通知 `OSDWIN1;CRTSTG1;CRTBLR1;CRTSCN1`、bit配置、OSD操作の互換性を維持する。4aのcoreでは走査線をNOT YETとして選択対象から外し、旧bypass coreの要求値画面も維持する。

OSD2はCRT READY - STAGE4B、SESSION ONLY / NO SAVE、CRT ENABLE、H BLUR、SCANLINE、APPLY、CLOSE、POSを表示する。OSD1との排他、5位置、入力遮断と終了後の全解放待ちを維持する。保存は未実装で、別ゲームで3項目をOFFへ初期化する。

## 検証状況

修正版の自動試験では、全8 bit値と9段階の行別減光量18,432画素、全16組合せ53,212,437画素、43 frameの位相・減光積分を照合した。走査線OFFの16,087,437画素は固定4aと、両効果OFFの8,662,437画素は導入前の映像と一致した。ぼかしの空間演算比較中だけ試験側のmemory書換えを停止し、走査線単体は独立した1 clock先読みmodelと継続書換え中も照合した。製品側にゲーム停止は追加していない。

設定再送、古い返信の拒否、A/B保持中の描画維持、長い能力返信中の設定・OSD受信とpending状態返信も試験する。既存ぼかし、frame一括反映、起動・入力も回帰試験の対象とする。

修正版firmware（221,136 byte）とNES image（4,640,660 byte）のbuildが成功した。FPGAのsetup/hold違反は0/0で、report掲載の最小pulse幅に負の余裕はない。clock制約は4aと同一。修正版の実機書込みと画質・操作の確認は未実施。修正版の記録は `verification/crt-stage4b-fix/` に保存する。初版の自動試験・build・導入記録は `verification/crt-stage4b/` に保持する。初版はsetup/hold違反0/0で導入したが、実機で上記の問題が見つかったため実機確認済みtagを作成していない。

## 修正版の実機試験

1. firmwareとNES imageを対応して導入し、通常起動・映像・音声・操作を確認する。
2. 左右とA/Bで3項目を変更する。A/B保持中も表示が追従し、操作を止めてもWAITINGからFRAME ACKへ移って要求値と映像が一致することを繰り返し確認する。OFFへの復帰も確認する。
3. CRT ENABLEをON、H BLURをOFFにして走査線の全強度を見る。元224行の模様がframe間でずれず、隣接行の濃さの分配で間隔の段差が和らいだか評価する。
4. ぼかし併用、画像位置、OSD文字の鮮明さ・表示維持、左右端、静止・動く場面での筋・ちらつきを確認する。
5. 5位置、OSD1との排他、ゲーム入力遮断と終了後の全解放待ち、同ゲームでの保持・別ゲームでのOFF初期化、日本語メニューとtitles.csv順序を確認する。

再試験が済むまで4bを完了にしない。他core・別表示機器・未試験のcontroller接続へ結果を一般化しない。
