# Console138K SNES ROM転送（SPI 32 MHz）

2026年11月12日の実機確認を、ROM転送高速化の到達点として記録する。共通tagは `spi32-continuous-hw-20261112`。親repositoryのsubmodule参照でBL616 firmwareとSNESTangの組を固定する。

## 通常版の構成

- SNES coreが `ROMXFR1`・`UART8M1`・`SPIDAT1` を通知すると、BL616がSPI Mode 1、32 MHzでDATAをDMA連続送信する。FPGAは150 MHzで入力を取り込み、各byteを確認応答付きで80 MHz側へ渡す。
- 制御とACKは従来のUARTを使う。各frameのCRC、再送、転送後にSDRAMから全ROMを読み戻すCRC照合を維持する。照合成功後にゲームを開始する。
- 実機で使用したfirmwareにはJTAG送信とROM識別の高速化、および一覧復帰処理も含まれる。短縮経路は最低1秒待機し、GPIOとFPGAの状態を確認する。短縮経路でmonitor書き込みに失敗した場合は、RELOADからやり直して5秒待つ経路を1回自動再試行する。
- 通常版では計測ログの出力を無効にした。

## 確認結果

16 MHzと32 MHzはいずれも連続送信ONの計測版。DATAはフレーム送信とACKを含む区間、ENDは全ROM読み戻し照合を含む区間。各条件3回の平均を示す。

| SNES ROM | DATA 16 MHz | DATA 32 MHz | DATA短縮率 | END 32 MHz |
| --- | ---: | ---: | ---: | ---: |
| 2 MiB（スーパーマリオコレクション） | 1.475秒 | 1.073秒 | 27.3% | 0.488秒 |
| 4 MiB（スーパードンキーコング） | 2.961秒 | 2.155秒 | 27.2% | 0.975秒 |

両周波数とも全12回でCRC照合に成功し、再送は0回だった。32 MHz通常版ではFlashの独立読み戻しが一致した。両タイトルを各3回起動し、映像・音声・操作・OSDからの一覧復帰に異常は報告されず、microSDに計測ログの追加はなかった。時間と再送回数は計測版で取得した。CRC異常・ACK消失・読み戻し不一致、および5秒待ちの自動再試行はPCの模擬試験で確認した。

## Build設定と実機確認済みイメージ

- BL616は `console138k`、`bl616`、`bl616dk`、C++17。実機版はBouffalo SDK `7f44f9ea6b4ccf96db8c5236c8024b68e2a76df7` とXuantie GCC 2.6.1（Windows）でbuildした。
- FirmwareのCMake設定は `TC_ROM_UART=ON`、`TC_ROM_SPI=ON`、`TC_ROM_CPU_PIPELINE=ON`、`UI16_SYSTEM_MENU=ON`、`UI16_SD_FONT=ON`、`UI16_RELIABLE_FONT=ON`、`TC_LAUNCH_TRACE=OFF`、`TC_ROM_PROFILE=OFF`、`UI16_UART_SELFTEST=OFF`。SDK設定は `CONFIG_DEBUG=y`、`CONFIG_ROMAPI=y`、`CONFIG_USB_HS=y`、`CONFIG_TLSF=y`、`CONFIG_COREDUMP=y`、`CONFIG_GCC_OPTIMISE_LEVEL=-Os`。
- SNES coreはGowin 1.9.12.04で `gw_sh build_console138k_usb.tcl console138k ds2` を実行した。`console138k_combined.sdc` に対するsetup・hold違反はともに0件だった。
